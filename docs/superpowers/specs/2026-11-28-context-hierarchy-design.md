# 上下文文件层级 — 设计

日期:2026-11-28 · 状态:设计已确认(对应 `docs/roadmap.md` 阶段一第 3 项)

## 意图

项目说明文件目前只读工作区根目录一层。monorepo 里子包目录开的会话吃不到仓库根的说明;子目录自己的约定(如 `src/` 下"改这里先看 X")更是完全没有入口。这次把装载升级为层级化:向上逐级查找、支持 `@路径` 导入、读到子目录文件时懒加载该目录的说明。

## 现状

- `loadProjectContext(cwd)` 在 REPL 启动(`REPL.tsx`)与 ACP `session/new`(`acp/session.ts`)各调一次,会话期不刷新;只读根目录 `CONTEXT_FILES` 五个名字,40K 字符总预算,超预算截断。
- 根目录是**全部命中都载入**(TRANS.md 和 CLAUDE.md 并存会两个都进提示词),与 roadmap"每级只取一个"不一致。
- 说明内容渲染为系统提示的 `## Project instructions`,每个文件一个 `### 相对路径` 小节。

## 设计

### 1. 向上逐级查找

- 从 cwd 向上走到 **git 仓库根**为止(子包会话能吃到仓库根说明;每级都查,含 cwd 与 git 根)。不在 git 仓库内时最多向上 **5 级**。
- 每级按现有优先级取**第一个命中**:`TRANS.md > AGENTS.md > CLAUDE.md > TRANSCODE.md > .transcode/AGENTS.md`。
- **行为变化**:根目录从"全部命中都载入"变为同样只取一个(优先 TRANS.md)。
- 40K 预算从**最近一级**开始分配(越近优先级越高);提示词里排序**根 → 最近**(一般到具体,更具体的靠后)。
- `~/.transcode/AGENTS.md` 这类用户级说明不并入此机制(用户记忆已承担该角色)。

### 2. `@路径` 导入

- 语法:整行 `@相对路径`,相对**导入文件所在目录**解析。
- 递归解析深度 ≤ **3**(导入的文件里还能再 `@` 两层);单个被导入文件 ≤ **64KB**,超限截断并标注。
- 环检测(循环导入跳过并标注);导入内容同样吃 40K 总预算。
- 仅认"整行"形式,行内出现的 `@xxx` 不处理,避免误伤正文提及。

### 3. 子目录懒加载

- `read_file` 读到目录 `X` 下的文件、且 `X` 存在说明文件(同名优先级列表,不含 `.transcode/AGENTS.md`)时,把该说明附在工具结果尾部,格式 `[(来自 X/AGENTS.md)] …`。
- 会话内每个目录只注入一次(去重);懒加载内容不进系统提示,只出现在工具结果里。
- 实现挂在 `tools/files.ts` 的 read_file 内部,loop 与权限层零改动。

### 4. REPL 与 ACP 同享

两个入口都走 `loadProjectContext`,自动获得全部行为。

## 非目标

- 说明文件的热重载(会话中途改 TRANS.md 不重载,维持现状)。
- 会话分叉/快照相关(阶段三文件快照之后再说)。
- `@` 导入的变量展开、条件导入等模板能力。

## 验收口径

- monorepo 子目录启动:根说明与各级说明按序进入提示词,总量不超 40K。
- `@` 导入:合法路径展开;超深/超大/成环各自安全降级并标注。
- `read_file` 触发懒加载:首次附说明、再次不重复;无说明文件零开销。
