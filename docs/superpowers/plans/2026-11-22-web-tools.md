# Web 工具(WebFetch + WebSearch)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** agent 联网能力:`web_fetch`(零配置抓网页)+ `web_search`(Tavily/Brave 适配器,用户配 `~/.transcode.json`)+ `/search` 交互配置命令。

**Architecture:** 抓取与搜索的**可测逻辑全部抽成纯函数/注入 fetch 的模块**(HTML 提取、charset 嗅探、两家 REST 适配器、配置归一化),工具壳只做组装;`web_search` 经 `AgentTool.isEnabled` 谓词在 `loop.ts:315` 每轮组装时按配置过滤;`/search` 复刻 `/models` 的 REPL 拦截 + phase 状态机模式,可测部分(provider 列表、测试查询、配置写入)留在模块层。

**Tech Stack:** TypeScript + Bun test + zod(已有);原生 fetch,零新依赖。

**Spec:** `docs/superpowers/specs/2026-11-22-web-tools-design.md`

## Global Constraints

- 零新依赖:HTML 提取、charset 嗅探、代理(不做)全部手写;不引 undici/turndown
- UA 固定:`Mozilla/5.0 (compatible; transcode/${VERSION})`(版本取 `src/version.ts`)
- 端点与鉴权按 spec:Tavily `POST https://api.tavily.com/search` body `{ api_key, query, max_results }`;Brave `GET https://api.search.brave.com/res/v1/web/search` 头 `X-Subscription-Token`、参数 `q`/`count`
- 上限:响应体 512KB、注入文本 20k 字符、超时 15s(`AbortSignal.timeout`)、`maxResults` 默认 5、上限 20
- 测试**不发真实网络**:fetch 以参数注入或测试内替换 `globalThis.fetch`(try/finally 恢复)
- 两工具 `kind: 'fetch'`、`isMutating: false`,经 `dispatchPool` 注册(ACP/子 agent 同享)
- 每任务收尾:`bun test` 全绿 + `bun run typecheck` 通过

## Review Focus

1. **GBK/GB2312 页面** → Content-Type/meta 嗅探 + `TextDecoder` 解码,中文不乱码(Task 1 测试)
2. **超大响应/超长文本** → 512KB 字节截断、20k 字符截断并注明(Task 1)
3. **403/404/超时/DNS 失败** → 可读错误返回模型,execute 永不向上抛(Task 1)
4. **webSearch 配置坏 vs 未配** → 坏:工具隐藏 + REPL 启动一行警告 + ACP stderr 一次;未配:全程静默(Task 2)
5. **/search 中途放弃(Esc)/空 key/测试查询失败** → 不写坏配置,可重输,phase 正确回落 idle(Task 3)
